# Практическая работа № 7

Вариант 10. Room «Автосервис».

## Сборка и запуск

Откройте папку `Labs10` в Android Studio. Для сборки нужны JDK 21 и Android SDK Platform 37.0. Выберите модуль `RoomLab10` в конфигурации запуска или выполните `./gradlew assembleDebug`. APK находится в папке `build/outputs/apk/debug` соответствующего модуля.

## RoomLab10 — Автосервис

Откройте приложение с чистой учебной базой и нажмите «Выполнить сценарий». В Logcat выберите тег `ROOM_LAB`. В сценарии 25 команд, включая проверки пустого имени, отсутствующего заказа, неверной даты и попытки записи с нарушением внешнего ключа. Для повтора используйте новый экземпляр приложения с пустыми данными.

- `masters` и `orders` связаны по `masterId` с индексом и каскадным удалением. Room хранит дату как число дней, конвертируя её в `LocalDate`.
- Через `BaseDao<T>` выполняются внесение, изменение и удаление. `addmany` работает в транзакции, поэтому при ошибке отсутствующего мастера весь пакет откатывается.
- `find` сравнивает результаты параметризованного запроса и фильтрации в Kotlin. `stat` показывает выручку, `join` связывает заказ с именем мастера, а Flow сообщает об изменении количества заказов.
- Схема Room экспортируется KSP в `RoomLab10/schemas`.

В Android Studio базу можно открыть через **App Inspection → Database Inspector**. До запуска обе таблицы пусты. После запуска должно быть 3 мастера и 2 004 заказа, из которых 2 000 созданы для замера. Выручка мастера № 1 после изменений составляет 13 600 ₽. Сравниваются 20 запусков двух способов. Индексированный SQL отбирает строки внутри базы, а `getAll().filter` каждый раз загружает все строки и обрабатывает их в приложении.

## Результаты проверки

Для Room в папке `evidence` есть Logcat и снимки экрана приложения до и после сценария. Содержимое таблиц сверено по копиям SQLite из эмулятора. В этом запуске 20 выборок через Kotlin заняли 34 мс, через SQL — 15 мс. Оба способа вернули по 299 одинаковых строк.
